## Token Reference

`theme/` (repo root) is the canonical import path. `components/hooks/useTheme.tsx` was a temporary backward-compat re-export (`export * from '@/theme'`) — **deleted in Phase 8** once its last importer (`app/_layout.tsx`) switched to `@/theme` directly. Every file in the app now imports from `@/theme`.

```
theme/
  colors.ts     — light/dark palettes (13 flat keys: background, surface, surfaceDeep,
                  ink, inkMuted, inkSubtle, inkHairline, accent, accentLight, accentMuted,
                  sage, warning, danger)
  spacing.ts    — space: { xs:4, sm:8, md:12, lg:16, xl:24, xxl:32, xxxl:48 }
  radius.ts     — radius: { sm:8, md:10, lg:14, xl:20, pill:100 }
  typography.ts — font.serif.{regular,italic}, font.sans.{light,regular,medium},
                  font.size: { xs:10, sm:11, base:12, md:14, lg:15, xl:18, xxl:22, display:52 }
  icons.ts      — icon: { xs:12, sm:16, md:18, lg:22, xl:26, xxl:32, hero:52 }
  shadows.ts    — getShadows(mode) -> { sm, md }, platform + mode aware
  index.tsx     — composes all of the above into Theme; hosts ThemeProvider, useTheme(), useThemeToggle()
```

Usage: `const T = useTheme();` then `T.ink`, `T.space.md`, `T.radius.lg`, `T.font.size.base`, `T.icon.md`, `T.shadow.sm`. Color keys stay flat (unchanged from the original hook) — new categories are namespaced.

## Architecture Decisions Log

- **2026-07-04** — Removed NativeWind/Tailwind entirely (zero `className` usages existed; it was fully wired into babel/metro config for no benefit). Standardized on `StyleSheet.create` + `theme/` tokens as the single styling paradigm and single token source of truth.
- **2026-07-04** — `theme/` created as a top-level directory (not nested under `components/hooks/`) — a design system is a first-class citizen, not a hook implementation detail.
- **2026-07-04** — Existing flat color keys (`T.ink`, `T.accent`, ...) kept unchanged; new token categories (`space`, `radius`, `font`, `icon`, `shadow`) added as namespaced groups to avoid any forced edits to the ~23 existing consumer files.
- **2026-07-04** — `components/hooks/useTheme.tsx` kept as a one-line re-export shim until Phase 8, so no consumer needs an import-path change until the final cleanup phase.
- **2026-07-04** — All `components/ui/` primitives consume theme via `useTheme()` internally — no `T`/theme prop threading. This retires the prop-drilling pattern seen in `menu.tsx`'s old `Section`/`MenuItem` (`T: Theme` prop).
- **2026-07-04** — `sleep-timer.tsx` / `volume.tsx`: confirmed with user — restyle shell only onto `BottomSheet` when Phase 7b is reached; do not implement the missing timer/volume-slider functionality as part of this effort. Tracked in `OUT_OF_SCOPE.md`.
- **2026-07-04** — Phase 7b executed: `sleep-timer.tsx`'s original Modal was already an exact structural match for `BottomSheet` (same radius/padding values, since `BottomSheet` was generalized from this very file) — a zero-override drop-in. `volume.tsx`, however, was actually built as an **anchor-measured popover** (`measureButton`/`UIManager.measureInWindow`, same pattern as `playback-speed.tsx`), not a bottom sheet, despite the plan's assumption both stubs shared sleep-timer's shape. Converting it to `BottomSheet` anyway was judged safe *specifically because* it's a non-functional stub — there's no real slider interaction to break, unlike `playback-speed.tsx`'s working speed picker (left alone in Phase 7a for that reason). The dead `measureButton`/`anchorPos`/`UIManager`/`findNodeHandle` scaffolding was removed along with it since a full-width `BottomSheet` needs no anchor position. Added a "Volume" title line to `volume.tsx` (previously titleless) to match `sleep-timer.tsx`'s established shell convention — the original "Volume slider here" placeholder text is kept underneath, unchanged in wording.
- **2026-07-04** — Player screen (Phase 7c): a size-matching judgment call, made explicit here since it cuts against a prior phase's reasoning. `player/[id].tsx`'s back chevron was 28px — not an exact `icon` token (26/32 are the neighbors) — but was converged onto `IconButton size="xl"` (26px) anyway, a deliberate 2px rounding. Rationale: this is a small, secondary, one-off control, and pulling stray sizes onto the token scale is exactly what the design system audit is for. By contrast, `controls.tsx`'s main transport icons (36px rewind/fast-forward, 76px play/pause) and `mini-player.tsx`'s 36px play/pause (Phase 6) were deliberately left alone — those are large, prominent, frequently-tapped controls with no close token neighbor, where forcing a size change risks a visible regression. The dividing line applied going forward: ≤2px from a token and a minor/secondary control → converge; anything larger or on a prominent control → leave as-is. `book-info.tsx`'s cover-art shadow (`shadowColor: T.accent`, custom opacity/radius/offset — an intentional accent-tinted glow) was left untouched rather than forced onto `T.shadow.sm`/`md`, which are both fixed black-shadow presets and would kill the accent tint. `seeker.tsx`'s `@react-native-community/slider` has no primitive equivalent (`ProgressBar` is display-only, non-interactive) — left as-is beyond the theme-import switch. All 4 files' `useTheme` import switched to `@/theme`; zero logic changes anywhere (unmount-save refs, query loading, seek-on-load, transport controls, seeker drag-to-seek all untouched).
- **2026-07-04** — Root layout + legacy removal (Phase 8): `app/+not-found.tsx` was the only remaining consumer of `components/Themed.tsx` (the old parallel `useThemeColor`/`Text`/`View` theme system) — rewritten onto `@/theme` with the same font/color conventions used everywhere else in the app (`DMSerifDisplay_400Regular` heading, `DMSans_400Regular` body, `T.accent` instead of the old hardcoded `#2e78b7` link color). With that gone, `Themed.tsx`, `components/hooks/useColorScheme.ts`/`.web.ts`, and the legacy `Colors` default export in `constants/constants.ts` had zero remaining importers (grep-confirmed) and were deleted. `app/_layout.tsx` also had a genuinely dead import — `useColorScheme` from the old hook path was imported but never called anywhere in that file — removed outright rather than migrated. `app/_layout.tsx`'s `ThemeProvider`/`useTheme` import switched from the shim to `@/theme` directly, which was the shim's last consumer; the shim (`components/hooks/useTheme.tsx`) was then deleted. Final grep across the repo for `hooks/useTheme`, `hooks/useColorScheme`, and `components/Themed` turns up zero remaining code references (two historical comments in `theme/colors.ts`/`theme/index.tsx` mention the old path by name but import nothing from it). **Noticed but not touched**: `constants/constants.ts`'s `AUDIO_EXTS` and `ROOT` exports have zero importers anywhere in the repo — likely genuinely dead, but unrelated to the theme-system cleanup this phase targets, so left alone and logged in `OUT_OF_SCOPE.md` instead of deleted speculatively.
- **2026-07-04** — Final audit (Phase 9): fixed two genuinely zero-risk stragglers found by the grep sweep — `app/_layout.tsx`'s and `app/(tabs)/_layout.tsx`'s `headerTitleStyle` blocks both had raw `fontFamily: 'DMSerifDisplay_400Regular'` sitting right next to `color: T.ink` in the same object, with `T` already in scope — converted both to `T.font.serif.regular` (identical string value, zero visual risk by construction, not a judgment call). `app/_layout.tsx`'s `fontSize: 18` also converted to `T.font.size.xl`, an exact match. `app/(tabs)/_layout.tsx`'s `fontSize: 20` was **left as a literal** — no token matches it exactly (18/22 are the neighbors) and, unlike Phase 7c's 2px icon rounding, this is header title text visible on every tab screen; a size change there is a more noticeable design decision than an audit fix, so it wasn't made unilaterally. Deliberately did **not** do a mass sweep of the remaining raw `fontFamily`/`fontSize`/`borderRadius` literals — the plan scopes Phase 9 as an audit-and-report, and a repo-wide rewrite touching ~19 files would be exactly the kind of "widespread change" that needs to be flagged and agreed to separately, not folded into a final-audit phase. The 2 hex-color literals found (`app/+html.tsx`) are excluded from the count on inspection: that file is static Node-rendered HTML/CSS for the web platform's `<head>`, runs with no React tree and no access to `useTheme()`, and its `#fff`/`#000` values are a `prefers-color-scheme` media-query fallback that can't reference theme tokens even in principle — not a design-system gap.
- **2026-07-04** — Confirmed with user: "3 parallel auth implementations" resolved by deleting the two dead ones (`useAuthGate.ts`, `auth-loading.tsx` — both unreferenced) rather than building a new unified abstraction. The single live implementation (inline in `app/_layout.tsx`'s `RootLayoutNav`) is untouched.
- **2026-07-04** — `downloads.tsx` (Phase 2): the status badge (previously a bare colored dot + uppercase text) is now the `Pill` primitive — an intentional visual refinement (adds a chip background/border) rather than a 1:1 port, since Pill has no bare "dot" variant. Per-file progress rows keep plain percentage text (no per-file bar) — matches the original, out of scope for this phase.
- **2026-07-04** — Library bundle (Phase 3): `Card` was **not** adopted for `book-card.tsx`'s or `inprogress-row.tsx`'s card surfaces, despite both being visually identical to `Card`. Both are the direct child of `<Link asChild>`, which clones its child and injects `onPress`/navigation behavior onto it — that only works because the child is a `TouchableOpacity`. Swapping it for `Card` (a plain `View`) would silently break tap-to-navigate. Kept as local `TouchableOpacity` + inline theme-token styles. `library-header.tsx`'s Rescan/Go-Online-Offline pills were similarly left as bespoke `TouchableOpacity`s rather than forced onto `Pill` — they swap an icon for a loading `ActivityIndicator` and change background/border by state, which the `Pill` primitive doesn't support without extending it beyond this phase's scope. All 5 library files' theme import switched from the `components/hooks/useTheme` shim to `@/theme` directly (mechanical, zero behavior change, advances Phase 8 shim retirement).
- **2026-07-04** — Book Details (Phase 4): extended `IconButton` with an optional `disabled` prop (dims to 0.35 opacity, passes through to the underlying `Pressable`) — its first real consumer (download/play/delete actions) needed disabled states the primitive didn't yet support. This is additive/backward-compatible, not a redesign. The three action icons and the cover's back button now use `IconButton`; the legacy `components/downloads/progress.tsx` (custom `Progress` ring) was replaced with `components/ui/progress-ring.tsx` (`ProgressRing`), and both it and the dead `components/common/loading-spinner.tsx` import were deleted as a result (see Cleanup Checklist). **Visual refinement, not a straight port**: `IconButton`'s built-in `T.space.sm` padding gives the download/play/delete icons a larger touch target and slightly more visual gap than the original bare `TouchableOpacity`s had — intentional, consistent with the primitive's convention, not flagged as a regression.
- **2026-07-04** — Login (Phase 5): `Button` (primary variant) and `Pill` primitives were exact drop-ins for the "Sign in" button and the two dev-mode toggle chips — both primitives were originally modeled on this exact screen's patterns, so no visual delta. `InputRow`'s `T: Theme` prop was retired in favor of an internal `useTheme()` call (same prop-drilling-removal pattern as `menu.tsx`'s `Section`/`MenuItem` in Phase 1). Form `Card` needed a style override (`borderRadius: T.radius.xl`, `padding: T.space.xl`, `gap: T.space.lg`) since its internal default radius (`T.radius.lg`/14) is smaller than this screen's original 20px card radius. Also fixed a stale comment referencing `useAuthGate` (deleted in Phase 0's Bucket A cleanup) — no behavior change, just removed a reference to code that no longer exists.
- **2026-07-04** — Tab layout + Mini Player (Phase 6): only `mini-player.tsx`'s hand-rolled bottom progress strip was replaced with `ProgressBar` (`progress`, `height={2}`, absolute-positioned via `style` override) — an exact functional match. Everything else in both files was deliberately left alone: `FlatTabBar`'s tab items (icon + label stacked, active/inactive color swap) have no matching primitive and building one now would be scope creep for a single 3-tab bar; the play/pause icon in `MiniPlayer` is sized 36px, which doesn't land on the `icon` token scale (32 or 26 are the neighbors) — forcing it onto `IconButton` would shrink or grow a prominent, frequently-tapped control by a few px for no benefit, so it stays a plain `TouchableOpacity`. Theme imports in both files switched to `@/theme`. Trivial cosmetic note: `ProgressBar`'s default `borderRadius: height/2` gives the mini-player's progress strip 1px rounded corners it didn't have before (was a hard rectangle) — imperceptible at a 2px height, not treated as a regression.
- **2026-07-04** — Player secondary controls, functional pair (Phase 7a): `chapters.tsx`'s trigger icon and hand-rolled Modal/backdrop/sheet chrome were replaced with `IconButton` (`icon="menu-book"`, `size="xl"` — 26px, an exact token match) and `BottomSheet` (this is literally the file `BottomSheet` was generalized from, via `sleep-timer.tsx`'s twin pattern — style-overridden for the 20px radius/asymmetric padding this screen already had). `playback-speed.tsx` was **not** migrated onto `BottomSheet` — its Modal is an anchor-measured popover positioned next to the trigger button (`measureButton`/`UIManager.measureInWindow`), a structurally different pattern from a full-width bottom sheet; forcing it would change the interaction, not just the look. Only its theme import was switched. `secondary-controls.tsx` (the shared container, not separately listed in the phase plan but touched here since all 4 buttons live in this folder) also had its theme import switched to `@/theme` — mechanical, zero behavior change. All chapter-switching/progress-sync logic (`switchChapter`, `getFileProgress`, `saveProgress`) and playback-speed logic (`setPlaybackRate`, `shouldCorrectPitch`) left untouched.

## Verification

For every phase, in this order:

1. `npm run typecheck` — must be clean
2. `npm test` — must stay green
3. Boot the app via the `run` skill, navigate to the screen(s) the phase touched
4. Drive the actual functionality via the `verify` skill (not just a visual check)
5. Check both light and dark mode (`useThemeToggle`'s System/Light/Dark)
6. Acceptance bar: no new TS errors/warnings, no behavior change, visually identical or an explicitly-noted intentional refinement
7. **Do not commit.** CLAUDE.md's standing rule: "Never commit code since I want to review it first." Each phase's changes are left as unstaged working-tree diffs for the user to review and commit themselves. Update this file's Status Table before starting the next phase, but leave git history to the user.
